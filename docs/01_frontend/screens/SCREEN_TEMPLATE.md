# 画面設計テンプレート

このテンプレートを基準に、今後の画面設計MDを作成する。

## 記述ルール
- HTML構造は画面単位のHTMLファイルに寄せる
- JavaScript は state 管理、イベント処理、API呼び出し、最小限の表示更新に寄せる
- 画面全体を `innerHTML` だけで再構築する前提にしない
- 画面固有の文言はこのMDに集約する
- 画面ごとに同じ見出し順で記述する
- 画面単位のMDファイル名には、必ず画面IDを含める
- ファイル名は `SCR-001_画面名.md` の形式を基本とする
- 画面単位で生成するソースファイル名にも、必ず画面IDを含める
- HTML、`app.js`、`service.js` は `SCR-001_...` のように画面IDを先頭へ付ける
- HTML、CSS、JavaScript には適切なコメントを記載する
- 特に JavaScript は処理概要、処理内容、主要な分岐、状態更新の意図が追える粒度でコメントする
- コメントは実装の補助として残し、処理の流れを読みやすくする

## 4. 画面構成
- header: 画面タイトル
- searchArea: 検索条件入力
- actionArea: 検索・クリアボタン
- messageArea: 件数・情報・エラーメッセージ表示
- resultArea: 検索結果一覧

## 9. 動作仕様

### 9.1 検索ボタン押下
1. 条件を取得する
2. APIを呼び出す
3. 結果を表示する
4. 件数を更新する
5. 0件やエラーの表示を行う

### 9.2 クリアボタン押下
1. 条件を初期化する
2. 結果を初期化する
3. 件数とメッセージを初期化する

## 15. ファイル構成

| 種別 | ファイル名例 | 役割 |
|------|--------------|------|
| HTML | `source/SCR-001_画面名.html` | 画面構造と主要文言を配置する |
| JS main | `source/js/SCR-001_画面名_app.js` | state管理、イベント処理、表示更新を行う |
| JS service | `source/js/services/SCR-001_画面名_任意名Service.js` | ダミーAPIや補助処理を行う |

## 16. 実装方針
- HTMLは画面単位のHTMLファイルに記述する
- JavaScriptは状態管理と処理に寄せる
- CSSは必要に応じて共通または画面専用で分ける
- 画面単位で実装し、不要なコンポーネント分割はしない
- HTML/CSS/JavaScript には設計意図が伝わるコメントを残す
- JavaScript は関数ごとに処理概要と処理内容が分かるコメントを付ける
