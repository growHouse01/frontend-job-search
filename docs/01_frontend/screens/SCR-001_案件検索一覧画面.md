## 2. 概要
案件を検索条件で絞り込み、検索結果を一覧表示する画面。

---

## 3. 画面目的
- 案件を検索する
- 案件の主要情報を一覧で確認する
- 結果件数を表示する

---

## 4. 画面構成
- header: 画面タイトル
- searchArea: 検索条件入力
- actionArea: 検索・クリアボタン
- messageArea: 件数・情報・エラーメッセージ表示
- resultArea: 検索結果一覧

- 備考: この画像のレイアウトを最優先の仕様とする。本文の説明よりも画像の配置、余白、ボタン位置、サマリーの並びを優先して実装すること。
- 備考: テキスト仕様と画像が矛盾する場合は、画像を正とし、必要に応じてテキスト仕様を補足または修正すること。

## 8. 初期表示
- projectName は空文字
- nationalityAllowed は "all"
- items は空配列
- totalCount は 0
- loading は false
- errorMessage は空文字
- infoMessage は空文字
- hasSearched は false

---

## 9. 動作仕様

### 9.1 検索ボタン押下
1. 検索条件を取得する
2. ダミー検索APIを呼び出す
3. 検索結果を一覧表示する
4. totalCount を表示する
5. 0件の場合は情報メッセージを表示する
6. 失敗時はエラーメッセージを表示する

### 9.2 クリアボタン押下
1. 検索条件を初期化する
2. 検索結果を空にする
3. 件数を0にする
4. メッセージをクリアする

## 15. 実装方針
- 画面のHTML構造は `source/SCR-001_画面名.html` に記述する
- JavaScript は state 管理、イベント処理、API呼び出し、最小限の表示更新に限定する
- 画面全体を JavaScript の innerHTML だけで再構築しない
- CSS は source/css/style.css に記述し、見た目の調整に利用する
- 画面は単一実装を基本とし、不要なコンポーネント分割はしない
- 画面単位で生成する `app.js` と `service.js` も画面IDを含めたファイル名にする
- HTML、CSS、JavaScript には適切なコメントを記載する
- 特に JavaScript は処理概要、処理内容、主要な分岐、state更新の意図が分かるコメントを入れる
- 関数単位で「何をするか」と「なぜそうするか」が追える粒度にする
- 実装時は必ず画面レイアウト画像を確認し、検索条件エリア、ボタン配置、件数表示、結果一覧の余白と並びを画像どおりに再現する
- 画像に写っている見た目の差分は軽微でも省略せず、レイアウト差分として扱う
